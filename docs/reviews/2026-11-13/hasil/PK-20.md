fixture Rp 1.000.000). Kategori "sewa" → lawan 6-2000 (`CASH_OUT_KEYWORDS`).

| Akun | Debit | Kredit |
|---|---:|---:|
| 6-2000 Beban Sewa | 250.000 | |
| 1-1110 Kas Kecil (akun kas dari jenis rekening) | | 250.000 |

Saldo R-K = 1.000.000 − 250.000 = **750.000** (mutasi yang menunjuk R-K). Ulang rujukan sama (U2) → kas & jurnal yang
sama, saldo tetap 750.000; rujukan sama Rp 300.000 (U7) → 409.

## Cara memakai pembuat kas (untuk PK-19, PK-22, PK-23, PK-24 dan unit berikutnya)

```python
from services import cash_ledger

txn = await cash_ledger.create_cash(
    entity_id=doc["entity_id"],          # PT dokumen induk — WAJIB, tidak pernah "all"/isi permintaan
    direction="out",                     # "in" | "out"
    amount=1_250_000,                    # > 0 (dibulatkan 2 desimal)
    ref_type="payroll_run", ref_id=run_id,  # WAJIB — dokumen induk; menentukan id tetap
    account_id=payload.account_id,       # rekening `bank_accounts`; "" → rekening tunggal PT untuk `cash_type`
    cash_type="kas_besar",               # dipakai HANYA untuk memilih rekening tunggal; jenis kas akhir dari rekening
    seq="",                              # isi bila satu dokumen melahirkan >1 kas searah (id pembayaran, langkah)
    txn_date=doc.get("paid_at", ""),     # kosong = sekarang; periode diperiksa untuk owner_entity_id or entity_id
    category="gaji", description="Bayar gaji Nov 2026",
    actor=actor["name"],
    contra_account_code="",              # lawan akun eksplisit (menang atas kata kunci kategori)
    owner_entity_id="",                  # PT buku jurnal bila beda dari PT kas
    counterparty_entity_id="",           # pasangan antar-PT (tampilan)
    journal_by_parent="",                # id jurnal induk / rujukan "<ref_type>:<ref_id>" bila JURNAL MILIK DOKUMEN INDUK
    txn_id="",                           # id turunan pemanggil (niat bayar, kasus); kosong = cash_ + SHA-1 rujukan
    extra={"payment_intent_id": iid},    # field tambahan; tidak bisa menimpa id/nominal/arah/PT/rekening/status
)
```

- **Isian wajib**: `entity_id`, `direction`, `amount`, `ref_type`, `ref_id`; rekening wajib *dapat ditentukan*
  (`account_id`, atau tepat satu rekening aktif PT untuk `cash_type`).
- **Urutan di dalam**: PERIKSA (tanpa tulisan) → upsert `$setOnInsert` id tetap (`gl_status: "pending"`) → jurnal
  `post_cash_durable` → kembalikan dokumen kas terbaru. Rujukan yang sama memakai dokumen yang ada (tidak ditimpa);
  kas lama ber-id acak (sebelum PK-20) untuk rujukan sama dan `seq` kosong ikut dipakai ulang. Kas di id tetap yang sudah
  `void` → kejadian baru di id `…|seq#2`.
- **Galat sebelum tulisan** — `CashRejected` (turunan `HTTPException`, siap dilempar ke router): 409 "Pilih rekening
  kas/bank untuk transaksi ini. {PT} punya {n} rekening {Kas Kecil/Bank}."; 409 "Rekening {nama} bukan rekening aktif
  {PT}."; 409 pesan periode tertutup; 409 "Transaksi kas untuk {rujukan} ini sudah tercatat dengan nominal {Rp}. Muat
  ulang lalu periksa."; 400 nominal/arah/rujukan kosong; 409 kas grup. Bila pemanggil harus memeriksa rekening LEBIH
  AWAL (sebelum efek lain, `02` §1 langkah 1), panggil `await cash_ledger.periksa_rekening(entity_id, account_id,
  cash_type)` → `{account, account_id, cash_type, account_code}` lalu teruskan `account_id` hasilnya.
- **Jurnal gagal** — `CashPostingError` (turunan `HTTPException` 409, pesan baku "Jurnal kas gagal: {galat}. Transaksi
  tersimpan dan bisa diulang dari Posting Gagal."); `exc.txn` = dokumen kas (`gl_status="failed"`, tampil di panel),
  `exc.error` = galat. Kas **tidak** dihapus. Pemanggil memutuskan: lanjut (uang sudah keluar, mis. kwitansi, refund,
  landed cost) atau gagalkan aksinya dan ulangi dengan rujukan yang sama (kas dipakai ulang).
- **Jurnal milik dokumen induk** (refund retur, gaji, antar-PT): `journal_by_parent=<id jurnal>` (atau rujukan bila
  jurnalnya terbit sesudah kas) → `gl_posted: true`, `gl_status: "not_required"`, `journal_entry_id` = id jurnal induk
  bila ada. Jenis rekening harus sama dengan `cash_type` jurnal induk (Bank ↔ 1-1100, Kas Kecil ↔ 1-1110).
- **Pendamping**: `next_cash_number(entity_id)` (satu-satunya pemberi nomor kas — pakai bila nomor harus dipesan lebih
  dulu, lalu kirim di `extra={"number": …}`); `ensure_posted(txn_id)` (jalur batal/ulang: memastikan jurnal kas asal
  ada; `CashPostingError` bila gagal); `record_return_cash(…, account_id="")` (refund retur/gaji).
- **Dilarang** (penjaga INV-CASH-01): `cash_transactions.insert_one/insert_many/replace_one/update_one(upsert=True)` di
  luar `cash_ledger.py`; memanggil `post_cash_transaction`/`_post_cash_transaction` di luar `gl_service.py`;
  `post_cash_durable` di luar `cash_ledger.py`/`posting_registry.py`; fungsi `_next_cash_number`.
- **Layar**: `components/CashAccountField.jsx` — `<CashAccountField entityId cashType value onChange onState />`;
  tombol simpan `disabled={… || cashAccountBlocked(state, value)}` dan alasan `cashAccountBlockReason(state)` ditulis
  di samping tombol.

## Menyimpang dari blueprint

1. **Isian `extra.number`**: nomor kas yang sudah dipesan (niat bayar PK-05, "nomor dipesan saat niat lahir") dikirim
   lewat `extra`; tanpa itu `create_cash` memberi nomor sendiri (`next_cash_number`).
2. **`journal_by_parent`** menerima id jurnal induk **atau** rujukan `"<ref_type>:<ref_id>"` (antar-PT dan penyelesaian
   per roll: jurnal terbit SESUDAH kas). `post_durable` menulis `journal_entry_id=""` untuk kas `not_required`; pembuat
   memulihkannya ke id jurnal induk bila ada (`parent_journal` menyimpan nilainya). Jenis rekening wajib sama dengan
   `cash_type` jurnal induk.
3. **Generasi sesudah `void`** (`…|seq#2`): rujukan yang sama sesudah kasnya dibatalkan (lepas biaya bank lalu catat lagi,
   batal titipan lalu titipkan lagi — PK-15 U12) membuat kejadian baru; spesifikasi diam soal ini.
4. **Biaya kampanye (baris 4)**: jurnal gagal → biaya **tetap tercatat** (status `posted`, `gl_status: failed`) dan kasnya
   tidak di-void; 409 "Jurnal biaya gagal: … tersimpan — jangan dicatat ulang; ulangi jurnalnya dari Keuangan › Posting
   Gagal." (dulu kas di-void & biaya dihapus). Id biaya acak per permintaan, jadi "dipakai ulang" hanya bermakna bila
   catatan biaya ikut disimpan.
5. **Refund keputusan selisih (baris 2)**: jurnal kas gagal → deposit tetap dikurangi dan keputusan tersimpan
   (`effect.refund.gl_status="failed"`), bukan galat — supaya keputusan yang diulang tidak melahirkan kas kedua (id
   keputusan acak). Urutan "deposit dulu, kas gagal → deposit dikembalikan" tetap milik PK-19.
6. **Niat bayar hutang (baris 9, 10)**: `create_cash` menjurnal kas di langkah sisip (dulu di langkah jurnal sesudah
   dokumen kontrabon); langkah jurnal kini `ensure_posted` dan tidak mengulang kas yang baru saja gagal di putaran yang
   sama (perilaku U6 PK-05 — 200 + peringatan — tetap).
7. **Kas antar-PT (baris 16)**: rekening Kas Kecil ditolak untuk pelunasan/pinjaman antar-PT (jurnalnya selalu 1-1100);
   `default_cash_account` kini memilih rekening Bank aktif pertama (dulu rekening aktif apa pun).
8. **Retur & gaji (baris 17)**: rekening diperiksa di awal tiap alur (bukan di `record_return_cash`) supaya penolakan
   terjadi sebelum stok/nota kredit/jurnal; isian API baru `refund_account_id` dan isian layar di tiga layar retur
   (tidak disebut spesifikasi — tanpa itu PT dengan dua rekening Bank tidak bisa refund tunai). Bayar gaji: parameter API
   `account_id` saja (layar di PY-T4).
9. **Pembalik kas** (batal kas manual, lepas biaya bank, batal titipan) dibungkus `post_durable(field="void_gl_status",
   raise_on_fail=True)` — perilaku tetap (gagal = tidak di-void), status pembalik kini tercatat; menutup tiga baris garis
   dasar posting ber-pemilik PK-20.
10. **Penjaga** juga mengecualikan berkas `test_*.py` di akar `backend/` (POC lama) dan menilai `update_many` /
    `find_one_and_update` ber-`upsert=True`.
