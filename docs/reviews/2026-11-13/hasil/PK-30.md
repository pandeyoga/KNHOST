## IC-02 — Roll dikirim utuh, dokumen memakai jumlah pesanan

- Berlaku di HEAD: ya (U1 tanpa jurnal `:adj:`, U2 409 roll lebih pendek, U3, U5b 500 sesudah roll pindah, U6 500).
- Akar masalah: tugas gudang memindahkan seluruh panjang roll pilihan, tetapi jurnal konfirmasi dan penerimaan pembeli
  memakai `subtotal` dokumen (jumlah pesanan), sedangkan HPP dan penilaian ulang roll memakai panjang aktual; jurnal barang
  baru diperiksa sesudah kepemilikan pindah.
- Perubahan perilaku (sebelum → sesudah):
  - `precheck_warehouse_task(transfer, *, periksa_jurnal=True)` (baca-saja): panjang aktual per produk = Σ panjang roll
    ber-`reserved_ref.id` tugas; berbeda > `QTY_EPS` dan pengaturan PT **penjual** `antar_entitas.selisih_panjang` =
    `tolak` → `IntercoLengthMismatch` (409, pesan spesifikasi); lalu `preflight_twin` jurnal penyesuaian dua sisi dan
    `preflight_entry` jurnal HPP & penerimaan, semuanya bertanggal hari ini (WIB).
  - `apply_length_adjustment(pair_id, actual, transfer, actor)`: dokumen sudah ber-`length_adjustment` → apa adanya;
    sama panjang → tidak menulis; selain itu kedua dokumen ditulis bersyarat (`length_adjustment` belum ada):
    `items[].quantity_ordered/quantity/line_subtotal`, `subtotal/tax_amount/grand_total` (rumus `_totals_from_items`,
    tarif & sakelar PPN dokumen), `length_adjustment`, `gl_status_adj`; jurnal `post_twin(base_id="{pair}:adj")` sisi
    `seller`/`buyer` (`_adj`), arah tabel spesifikasi (selisih total 0 → tanpa jurnal); faktur pajak internal terbit
    → `flag_needs_replacement`; saldo antar-PT proyeksi dihitung ulang.
  - `repost_length_adjustment(pair_id, actor)`; panel Posting Gagal jenis **`interco_adj` "Penyesuaian Panjang
    Antar-PT"** (saringan `gl_status_adj: failed`, nominal = |selisih total|, galat `gl_error_adj`).
  - (b) `approve_transfer`: transfer ber-`interco_pair_id` → `precheck_warehouse_task` sebelum klaim (galat → 409,
    tanpa tulisan); `on_warehouse_task_executed(..., actual=)` memanggil `apply_length_adjustment` sebagai langkah
    pertama, lalu penilaian ulang roll dan `post_gl_on_delivery` membaca `subtotal` baru. `create_warehouse_task`: mode
    `tolak` + panjang beda → reservasi dilepas + 409. Roll pilihan yang lebih pendek dari pesanan kini direservasi
    (dulu 409) — lihat "Menyimpang".
  - Kunci `antar_entitas.selisih_panjang` (`config_catalog_interco.py`, `pajak-pembukuan`·`antar-pt`, enum sesuaikan ·
    tolak, bawaan `sesuaikan` = K-07, global+PT, risiko tinggi + alasan, izin `accounting.manage`, pemakai
    `services/interco_service.py:precheck_warehouse_task`).
- Contoh angka (`00` §9; `bukti/PK-30/contoh_angka_U1.log`, database tiruan, KSC → Kanda, tanpa PPN, pesan 100 m @
  Rp 25.000, roll pilihan 130 m berbiaya Rp 18.000/m):

| Kejadian | Buku | Jurnal | Hitung tangan |
|---|---|---|---|
| Konfirmasi | KSC `:seller` | D 1-1250 2.500.000 · K 4-1000 2.500.000 | 100 × 25.000 |
| | Kanda `:buyer` | D 1-1310 2.500.000 · K 2-1250 2.500.000 | |
| Penyesuaian (setujui tugas) | KSC `:adj:seller` | D 1-1250 750.000 · K 4-1000 750.000 | (130 − 100) × 25.000 |
| | Kanda `:adj:buyer` | D 1-1310 750.000 · K 2-1250 750.000 | |
| Barang | KSC `:cogs` | D 5-1000 2.340.000 · K 1-1300 2.340.000 | 130 × 18.000 |
| | Kanda `:receipt` | D 1-1300 3.250.000 · K 1-1310 3.250.000 | subtotal baru 130 × 25.000 |

  Saldo dari pasangan ini: KSC 1-1250 = 3.250.000; Kanda 2-1250 = 3.250.000 (kredit); Kanda 1-1310 = 2.500.000 +
  750.000 − 3.250.000 = 0; Kanda 1-1300 = 3.250.000 = nilai roll pembeli 130 × 25.000; KSC pendapatan 3.250.000,
  HPP 2.340.000. Kedua dokumen: `quantity_ordered` 100 → `quantity` 130, `grand_total` 3.250.000; Saldo Antar-PT
  KSC→Kanda (proyeksi) 3.250.000. Sebelum PK-30 (HEAD): pembeli D 1-1300 2.500.000 untuk roll senilai 3.250.000 (selisih
  750.000 di buku besar vs buku roll), penjual pendapatan 2.500.000 untuk HPP 130 m.

## IC-10 — Harga dan mode PPN antar-PT bebas; status PKP tidak divalidasi

- Berlaku di HEAD: ya (U9/U10 200 dengan harga ketikan; U11 aksi tidak dikenal; U12 penjual non-PKP memungut PPN;
  U13 tanpa potret PKP).
- Perubahan perilaku (a) di `interco_service.create` (juga dipakai konversi Permintaan Internal dan wizard):
  - Penyimpangan = `pricing_mode`/`ppn_mode` isi permintaan ≠ pengaturan PT penjual, atau `unit_price` baris berbeda
    > 0,005 dari `_resolve_price(…, None, mode)` (kontrak belum ada = tanpa standar = menyimpang). Harga ketikan yang
    sama dengan kontrak dianggap harga kontrak.

    ≥ 5 huruf (400) — sebelum nomor & dokumen. `terms_override` di kedua dokumen + jejak `interco_terms_overridden`.
  - Ber-PPN dengan penjual non-PKP → 400 "PT penjual {nama} bukan PKP, …"; pembeli non-PKP → dibuat dengan
    `tax_warning="pembeli_non_pkp"`, jurnal tidak berubah; `seller_is_pkp`/`buyer_is_pkp` dipotret.
  - Izin baru `interco.override_terms` di empat tempat (`02` §3.2): `permissions_config.PK30_OVERRIDE_TERMS_ROLES`
    (Admin, Manajer), `access_modules` label "Ubah harga/PPN di luar kontrak" (modul `interco`, tanpa id menu baru),
    pemeriksa `has_permission(..., "interco", "override_terms")`, layar `can(perms, "interco", "override_terms")`, uji
    U11 (Tanpa Acuan 200, Manajer Kosong 403).
  - `IntercoCreate.override_reason`; `InternalRequestConvert.override_reason` + 403 (`InternalRequestForbidden`).
  - (b) Form Transaksi Antar-PT Baru: harga baris, Mode harga, Mode PPN terkunci tanpa izin (keterangan tertulis);
    pilihan pertama "Ikuti pengaturan PT penjual ({nilai})" dari `GET /api/interco/meta?seller_entity_id=` (field baru
    `defaults`); begitu menyimpang muncul isian wajib **Alasan mengubah harga/PPN**. Rincian: tiga kalimat spesifikasi.
