## Menyimpang dari blueprint

1. **"Void" tampil sebagai "Anulir"** (tombol "Anulir", lencana "Dianulir", pesan 409 "…berstatus Dianulir, jadi tidak
   bisa dianulir."). Glosarium `KN_32` (Void → Anulir) dan penjaga `audit_i18n_id.py` (103 → 109 bila "Void" dipakai;
   `02` L1: tidak boleh bertambah). Id endpoint/izin tetap `void` (`POST …/void`, `payroll.void`). Spesifikasi tidak
   menulis "menyimpang dari standar", jadi standar yang menang.
2. **Teks pengaturan `gl.tanggal_jurnal_periodik`**: pilihan "Hari saat diposting" → "Hari saat jurnalnya dibuat"; dampak
   & contoh tanpa "diposting" (penjaga INV-CFG-TXT menolak kata `posting`/`diposting`, sama dengan PK-37). Kelompok
   `keuangan-dasar` = alias `pajak-pembukuan` sub-judul `tutup-buku` (KF-T4; kini 12 kunci ≤ 14).
3. **Penyusutan**: `skipped` tetap jumlah (layar Aset Tetap menulis "{n} dilewati"); alasan per aset di daftar baru
   `skipped_assets[]` (`{asset_id, number, name, expected_period, reason: "periode melompat — …"}`). Periode tertutup
   salah satu PT → 409 sebelum aset mana pun diklaim (dulu klaim periode tertinggal lalu jurnal gagal).
4. **Akrual insentif manual** (`POST /api/sales/incentive/post-gl`): tidak lewat `post_durable` (tidak ada dokumen; gagal
   = 400/409 tanpa tulisan) → `post_incentive_accrual` masuk `TANPA_DOKUMEN` penjaga INV-POST-01 beralasan. Akrual yang
   menyertai posting gaji lewat resep `posting_registry.post_payroll` DI DALAM `post_durable` (jenis `payroll_run`).
5. **Bayar & anulir**: jurnal bayar dan pembalik lewat `post_durable` (`pay_gl_status`, `void_gl_status`) dengan
   `raise_on_fail` → status kembali `posted` dan galat tampil di layar (perlu isian pengguna: rekening, alasan), tidak
   menunggu di panel. Jurnal bayar juga berkunci id proses (spesifikasi hanya menyebut posting; P4).

   masa itu termasuk yang `pending` (dua setoran bersamaan tidak melampaui sisa; niat yang melampaui dihapus lagi
   sebelum kas — INV-ATOMIC-01).
7. **Mode "Semua PT" pada POST setoran**: ditolak lebih dulu oleh pagar tulis `entity_write_guard` (409 "Mode “Semua

## Data lama (H3) — kueri baca-saja untuk integrator (belum dijalankan; lingkungan A dilarang untuk pelaksana)

Kunci jurnal gaji berubah ke id proses. Proses lama dikenali lewat `journal_id`; yang `posted`/`paid` tanpa `journal_id`
dan tanpa `journal_date` memakai kunci lama bila jurnal berkunci lama ada (`gl_service.payroll_source_id`). Hitungan:

```js
// 1) proses diposting/dibayar tanpa journal_id (RISIKO spesifikasi)
db.hr_payroll_runs.countDocuments({status: {$in: ["posted", "paid"]},
  $or: [{journal_id: {$exists: false}}, {journal_id: {$in: [null, ""]}}]})
// 2) rinciannya + apakah jurnal berkunci lama "{PT}:{periode}" ada
db.hr_payroll_runs.find({status: {$in: ["posted", "paid"]}, $or: [{journal_id: {$exists: false}}, {journal_id: {$in: [null, ""]}}]},
  {_id: 0, id: 1, number: 1, entity_id: 1, period: 1, status: 1}).forEach(r => printjson({...r,
  jurnal_lama: db.journal_entries.countDocuments({source_type: "payroll_run", source_id: r.entity_id + ":" + r.period, status: {$ne: "void"}})}))
```
