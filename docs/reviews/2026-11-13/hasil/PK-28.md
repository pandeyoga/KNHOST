## IV-03 — akun GR/IR tidak pernah kembali nol per PO

- Berlaku di HEAD: ya. Bukti kode lama (`bukti/PK-28/perilaku_kode_lama_U1_U5.txt`, skrip `skrip_perilaku_lama.py` di salinan
  bersih `c3eb0a2`): faktur 100 m @ 11.000 atas penerimaan 100 m @ 10.000 → Dr 2-1150 **1.100.000** / Cr 2-1100 1.100.000,
  sisa GR/IR PO **−100.000** mengendap; retur 20 m sebelum ditagih → boleh-tagih tetap **100**, faktur 100 m **diposting**,
  sisa GR/IR PO **−222.000** (termasuk PPN 22.000 yang tidak pernah dicatat sebagai PPN masukan).
- Akar masalah: faktur menghapus GR/IR sebesar nilai faktur, bukan nilai penerimaan; retur sebelum faktur mengurangi GR/IR
  tetapi tidak mengurangi qty boleh-tagih, dan membalik PPN masukan yang belum ada; tidak ada daftar sisa per PO maupun
  jalan resmi untuk membersihkan sisa yang tidak akan tertagih.
- Perubahan perilaku (sebelum → sesudah):
  - Faktur ber-PO: Dr GR/IR = Σ qty tagih × harga neto baris PO (`grir_amount`); selisih neto faktur − `grir_amount` → akun
    `pembelian.selisih_harga` (debit bila lebih mahal, kredit bila lebih murah) **bila akun itu dipetakan untuk PT faktur**;
    belum dipetakan → perilaku lama dan `price_variance_posted=false` (terlihat di daftar GR/IR dan rincian faktur).
  - Retur beli menyimpan `ap_basis` (`gr_ir`/`hutang`/`kas`, aturan memilih tidak berubah). Dasar `gr_ir`: Dr GR/IR **tanpa
    PPN**, tanpa baris PPN masukan; qty-nya mengurangi boleh-tagih di 3-way match (dua mode) dan konteks tagih
    (`returned_unbilled_qty`). Dasar `hutang`/`kas`: jurnal tidak berubah.
  - Jurnal baru `goods_receipt`, `vendor_bill`, `purchase_return`, `grir_clearing` membawa `ref.po_id`.
  - Baru: Keuangan › Hutang › **GR/IR (Diterima Belum Ditagih)** (`GET /api/finance/gr-ir`, `vendor_bill.view`) — sisa per PO
    dari buku besar, umur, ember umur, pencocokan dengan saldo akun; **kliring** (`POST /api/finance/gr-ir/{po_id}/clear`,
    `accounting.manage`) lewat pintu tahan-gagal, jenis `grir_clearing` di Posting Gagal.
  - Tutup-kurang PO menyimpan `grir_balance` dan tindak lanjut Finance `grir_clearing` (tanpa jurnal otomatis).

| Penerimaan 100 m (`goods_receipt`, `ref.po_id`) | 1-1300 Persediaan | 1.000.000 | | 100 × harga neto baris PO 10.000 (`po_line_net_unit_price`) |
| | 2-1150 GR/IR | | 1.000.000 | |
| Faktur 100 m @ 11.000 (`vendor_bill`) | 2-1150 GR/IR | 1.000.000 | | `grir_amount` = 100 × 10.000 |
| | 5-9920 Selisih harga | 100.000 | | `price_variance_amount` = neto 1.100.000 − 1.000.000 |

Buku pembantu: sisa GR/IR PO = 1.000.000 − 1.000.000 = **0** (daftar: diterima 1.000.000, ditagih 1.000.000); hutang faktur
`outstanding` 1.100.000 = kenaikan 2-1100 1.100.000. Kode lama: Dr 2-1150 1.100.000 → sisa −100.000.

### Contoh angka U5 — retur sebelum ditagih

PO 100 m @ 10.000, PPN 11 %. Penerimaan 100 m: Cr 2-1150 1.000.000.

| Dokumen | Akun | Debit | Kredit | Hitungan |
|---|---|---:|---:|---|
| Retur 20 m (`ap_basis="gr_ir"`) | 2-1150 GR/IR | 200.000 | | 20 × 10.000 (tanpa PPN 22.000) |
| | 1-1300 Persediaan | | 200.000 | |
| Konteks tagih | — | | | diterima 100 − ditagih 0 − diretur belum ditagih 20 = **80** |
| Faktur 100 m | — | | | 400 "3-way match GAGAL" (100 > 80) |
| Faktur 80 m @ 10.000 | 2-1150 GR/IR | 800.000 | | 80 × 10.000 |
| | 1-1500 PPN Masukan | 88.000 | | 11 % × 800.000 |

## Menyimpang dari blueprint

1. **Dasar retur ditentukan sebelum jurnal**, bukan dikembalikan `post_purchase_return`: `gl_service.purchase_return_basis`
   (aturan lama) dipanggil di langkah NIAT, `ap_basis` ditulis bersama `gl_status: pending`, lalu diteruskan
   (`post_purchase_return(..., ap_basis=)`). Alasan `02` §1: niat tercatat sebelum jurnal; ulang posting memakai dasar
   tersimpan walau faktur terbit di antaranya. Tanpa `ap_basis` (pemanggil lain) fungsi menghitungnya sendiri.
2. **`price_variance_posted`** ditulis awal `abs(selisih) ≤ 0,005` pada tulisan `posted`; jurnal yang memuat baris selisih
   mengubahnya ke `true` (berlaku juga untuk ulang dari Posting Gagal sesudah akun dipetakan).
3. **Kliring — pemeriksaan tambahan**: unsur `grir_clearings[]` berstatus `failed` → 409 "Kliring GR/IR sebelumnya untuk PO …
   belum terjurnal. Ulang dari Tutup Buku › Posting Gagal dulu." (kliring baru = jurnal ganda saat unsur lama diulang);
   unsur `pending` → 409 pesan spesifikasi. NIAT bersyarat juga "larik tidak berubah sejak saldo dibaca"
   (`grir_clearings.<n>` belum ada) supaya dua kliring berurutan cepat tidak sama-sama memakai saldo lama.
