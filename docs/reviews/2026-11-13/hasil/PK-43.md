## UX-08 — Pelunasan antar-PT dari sisi PT pembayar

- Berlaku di HEAD: ya (U1 `KeyError: 'outstanding'`, U2 200 ≠ 403, U3 pesan lain; U4 jest: kandidat kosong).
- Akar masalah: pop-up menyaring kandidat dari daftar transaksi halaman induk (dimuat untuk PT aktif, baris
  `role="seller"`), jadi PT pembayar tidak pernah melihat tagihannya; isian tanggal dan rekening tidak ada.
- Perubahan perilaku (sebelum → sesudah):
  - Server `GET /api/interco/payment-schedule`: pasangan disebut → salah satu PT wajib dalam penugasan pelaku, selain itu
    403 "Anda tidak ditugaskan di salah satu PT pada pasangan ini." Tiap baris + `outstanding` (= `remaining`) +
    `settleable` (status terbuka **dan** jurnal kedua dokumen kembar tidak gagal) + `settle_block_reason`.
  - `POST /api/interco/settlements` (bentuk tetap): `bank_account_id` yang dikirim bukan milik PT pembayar → 400
    "Rekening bukan milik PT pembayar." sebelum apa pun ditulis (`interco_service.create_settlement`, sesudah cara bayar
    divalidasi; netting tidak memakai rekening).
  - Layar: pop-up **Pelunasan Antar-PT** memuat kandidat dari server setiap PT pembayar/penerima berubah (prop
    `transactions` dicabut); kolom Nomor · Tanggal · Jatuh Tempo · Total · Sisa · Dilunasi (bawaan = sisa; isian rupiah
    bila pengaturan jadwal bayar membolehkan bayar sebagian, selain itu nominal tetap + keterangan); memuat = kerangka
    abu-abu, galat = pesan + **Coba lagi**, kosong = "Tidak ada tagihan antar-PT yang terbuka untuk pasangan PT ini.";
    kotak cari nomor tagihan; baris berjurnal gagal tidak bisa dicentang (alasan tertulis). Isian **Tanggal pelunasan**
    (`interco-settle-date`, bawaan `todayWib()`) dan **Rekening {PT pembayar}** (`interco-settle-account`, rekening bank
    aktif PT pembayar — Kas Kecil tidak ditawarkan karena server menolaknya; disembunyikan untuk netting). Kirim:
    `settle_date`, `bank_account_id`, Idempotency-Key `ic-stl-…`, penahan klik ganda, konfirmasi "Lunasi {n} tagihan
    senilai {rupiah} dari {PT pembayar} ke {PT penerima} pada {tanggal}?", tombol **Terbitkan Pelunasan**; tombol mati →
    alasan ditulis di sampingnya.
  - Layar Antar-PT: tombol kepala **Buat Pelunasan** (dulu "Buat Settlement") tampil menurut izin `interco.settle` (izin
    endpoint-nya; dulu `interco.create`); tombol baris Saldo Antar-PT dan teks pengingat saldo menganggur ikut menjadi
    "Buat Pelunasan" (glosarium KN_32: "Pelunasan Antar-PT").
- Fixture vs proses: dokumen kembar `ICT-1` dan rekening disisipkan langsung; permintaan diuji lewat HTTP.
- Status: implemented_pending_review

## UX-13 — Telusur Laporan Keuangan → akun → jurnal → dokumen, dan kembali

- Berlaku di HEAD: ya (U5 `KeyError: 'opening_balance'`, U7 total 3 ≠ 2, U8/U9 `KeyError: 'source_doc'`; jest: tidak ada
  `fs-line-*`, `gl-back-to-report`, `gl-journal-open-source`).
- Perubahan perilaku:
  - `GET /api/gl/accounts/{code}/ledger?start=`: `lines` hanya `start ≤ tanggal ≤ as_of`, `opening_balance` (saldo
    sebelum `start`, tanda saldo normal), `period {start, end}`, saldo berjalan dari saldo awal; tiap baris `source_id`.
    Tanpa `start` bentuknya tetap (U6). Tanggal tidak berbentuk `TTTT-BB-HH` → 400; `start > as_of` → 400.
  - `GET /api/gl/journal?start=&end=` (biasa dan berhalaman; satu pembentuk saringan `_journal_query`).
  - `GET /api/gl/journal/{id}` + `source_doc` (`doc_refs_service.journal_source_doc`): `null` untuk `manual`, `closing`,
    `reversal`, `suspense_reclass` atau dokumen tidak ditemukan; selain itu `{doc_type, doc_id, number, label, link,
    link_hidden}`. `link` = `{view, focus_type, focus_id, tab}` dari `node_of` (peta PK-44) atau `null` bila PT dokumen di
    luar penugasan (`link_hidden="pt"`) atau izin lihat modul sumbernya tidak dipegang (`"izin"`, penyaring PK-17).
    Jurnal kembar antar-PT (`{pair_id}:{sisi}`) → dokumen pasangan di buku PT jurnal itu.
  - Laporan Keuangan: nama akun Laba-Rugi/Neraca = tautan `fs-line-{kode}` ("Lihat mutasi akun ini") →
    `go("general-ledger", { preset: { tab: "ledger", code, start, end, from: "financial-statements", fromTab } })`
    (Neraca: `end` = tanggal neraca tanpa `start`); hanya bila peran boleh membuka Jurnal & Buku Besar (`canOpen`).
  - Jurnal & Buku Besar: membaca preset (`useViewPreset`), tombol **← Kembali ke Laporan Keuangan** (`gl-back-to-report`)
    di bilah sendiri di atas tab → kembali ke tab dan periode asal (Laba-Rugi `start`/`end`, Neraca tanggalnya). Tab
    Buku Besar: isian **Dari**/**Sampai** (`gl-ledger-start`/`gl-ledger-end`), baris pertama **Saldo awal** bila Dari
    diisi (mutasi urut lama → baru), tiap baris membuka rincian jurnal (`gl-ledger-row-{nomor}`), kosong "Tidak ada mutasi
    pada rentang ini.". Aksi anulir/balik rincian dari buku besar = tab Jurnal (`useJournalActions`).
  - Rincian jurnal: bilah **Dokumen sumber** → **Buka Dokumen Sumber** (`gl-journal-open-source`, `onOpenDocument` dari
    `AppViewRouter`); tanpa tautan: "{label} {nomor} — di luar PT Anda" / "— Anda belum punya akses untuk membukanya";
    `null` → tanpa bilah. Bilah "← Kembali ke Jurnal & Buku Besar" di layar dokumen membuka buku besar dengan preset
    yang sama (`goBack` meneruskan `origin.preset`).
- Fixture vs proses: jurnal lewat `gl_service._insert_entry` (fixture); permintaan lewat HTTP.
- Status: implemented_pending_review

## Menyimpang dari blueprint

1. **Buku besar berentang urut lama → baru** bila Dari diisi (supaya "baris pertama Saldo awal" dan saldo berjalan
   terbaca dari atas); tanpa Dari tetap terbaru dulu seperti sebelumnya.
2. **`settleable` juga salah bila jurnal transaksi (salah satu sisi) gagal** + `settle_block_reason` — server menolak
   pelunasan seperti itu (409), jadi layar mengunci barisnya lebih dulu.
3. **`source_doc.link` juga kosong bila izin lihat modul sumber tidak dipegang** (`link_hidden="izin"`, penyaring PK-17;
   tujuan akan 403); teks layar menyebut alasannya. Jurnal kembar antar-PT (`{pair_id}:{sisi}`) dicari lewat `pair_id` +
   PT jurnal — tanpa ini `source_doc` selalu `null` untuk jurnal antar-PT.
4. **Pemeriksaan rekening di layanan** (`create_settlement`, sebelum menulis) dan hanya untuk metode non-netting.
5. **Tombol kembali ke laporan memulihkan periode** (bukan hanya tab): Laba-Rugi `start`/`end`, Neraca tanggalnya. `from`
   berupa teks (spesifikasi) sehingga bilah PK-44 tidak ganda; `goBack` PK-44 kini meneruskan `origin.preset`.
6. **Tanggal dokumen butir `posting_gagal`**: registri posting tidak punya field tanggal; dipakai urutan
   `tanggal_buku, txn_date, receipt_date, bill_date, settle_date, return_date, doc_date, date, acquisition_date, period,
   created_at` (dokumen tanpa tanggal tetap dihitung).
7. **Antar-PT: sisa dokumen = keadaan hari ini** (spesifikasi "sisa dokumen terbuka"), buku besar per `end_date`; ditulis
   di keterangan butir. Rekonsiliasi persediaan juga keadaan hari ini.
8. **Nama tombol "Buat Settlement" → "Buat Pelunasan"** (kepala, Saldo Antar-PT, teks pengingat, deskripsi job) + uji lapis
   A `test_g6b_poc.py` disesuaikan; tombol kepala kini menurut `interco.settle`.
9. Tombol **Buka** daftar periksa menambah `from: {view: "closing"}` di layar (bukan di jawaban server) → bilah "← Kembali
   ke Tutup Buku"; Antar-PT membaca preset tab (`balances`).
