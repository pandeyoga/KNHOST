## FE-02 — Kontrol pilihan Interco tidak memperbarui nilai
- **Berlaku di HEAD:** ya — direproduksi di browser sebelum perubahan: pilih "Kanda Fabric" sebagai
  PT Pembeli → kembali "Pilih...".
- **Akar masalah:** `KNSelect` hanya mendestrukturisasi `onValueChange` (tanpa `...rest`); 9 pemanggil
  Interco memakai `onChange`, sehingga callback tidak pernah dipanggil.
- **Perubahan perilaku:**
  - 9 lokasi memakai `onValueChange`: penjual, pembeli, mode harga, mode PPN, produk per baris
    (`IntercoCreateModal`), filter peran (`IntercoPanels`), pembayar, penerima, metode (`IntercoSettlementModal`).
  - `KNSelect` mencetak `console.error` di mode development bila dipanggil dengan `onChange` tanpa
    `onValueChange` (kontrak tidak berubah, hanya tidak lagi senyap).
  - Guardrail baru `scripts/guardrails/verify_knselect_contract.py` (didaftarkan di `scripts/gate.sh`)
    gagal bila ada `<KNSelect onChange=…>` tanpa `onValueChange`.
  - **Terkait (perubahan terpisah, sesuai arahan "uji dulu bentuk prop"):** `selectedEntity` dari App
    berupa **ID string** (`"all"` = semua PT), sedangkan `IntercoView` membaca `selectedEntity?.id` →
    selalu `""`. Akibat terukur dengan PT aktif Kanda: penjual bawaan = **Sukacita** (PT pertama),
    pembayar settlement kosong, semua permintaan `entity_id=`. Kini string & objek `{id}` didukung.
- **Berkas berubah:** `frontend/src/features/finance/interco/IntercoCreateModal.jsx`, `IntercoPanels.jsx`,
  `IntercoSettlementModal.jsx`, `IntercoView.jsx`, `frontend/src/components/KNSelect.jsx`,
  `scripts/guardrails/verify_knselect_contract.py`, `scripts/gate.sh`.
- **Pengujian (browser lokal, bukti DOM + jaringan):**
  - Transaksi Baru (PT aktif KSC): pembeli → "Kanda Fabric"; mode harga → "Sesuai HPP penjual";
    PPN → "Tanpa PPN"; produk baris 1 → "BTK-MEGA-001 · Batik Mega Mendung Premium" — semua tersimpan.
  - **Payload** `POST /api/interco/transactions` (disadap di browser lalu dibatalkan, tidak ada transaksi
    dibuat): `{"seller_entity_id":"ent_ksc","buyer_entity_id":"ent_kanda","pricing_mode":"at_cost",
    "ppn_mode":"tanpa_ppn","items":[{"product_id":"prod_batik_mega","quantity":5,"unit_price":null}],"submit_now":true}`.
  - Buat Settlement: pembayar → Sukacita, penerima → Kanda Fabric, metode → Kas — tersimpan.
    Tombol "Terbitkan Settlement" tetap nonaktif karena data acuan belum punya transaksi Interco
    terbuka untuk dilunasi (bukan bug kontrol pilihan).
  - Filter peran → "Sebagai Penjual" → `GET /interco/transactions?…&role=seller`.
  - Bentuk prop: PT aktif Kanda → sebelum: penjual "Sukacita", `entity_id=`; sesudah: penjual &
    pembayar "Kanda Fabric", `GET /interco/transactions?entity_id=ent_kanda`.
  - Guardrail: 0 temuan pada kode sekarang; versi `IntercoPanels.jsx` di `f4e8f0b` → 1 temuan (bukti-merah).
- **Fixture vs proses nyata:** tidak ada fixture; data acuan + interaksi UI nyata. Pengiriman transaksi
  sengaja dibatalkan di lapisan XHR agar tidak memposting jurnal/stok di data acuan.
- **Dampak modul terkait:** hanya layar Interco (daftar, form transaksi, settlement, kotak retur masuk
  & pinjaman yang menerima `entityId`). API tidak diubah; validasi pihak/produk/rekening/scope tetap di backend.
