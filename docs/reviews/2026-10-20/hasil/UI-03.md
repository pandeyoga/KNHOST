## FE-03 — Peta modul akses tidak mengikuti menu/hub terbaru
- **Berlaku di HEAD:** ya — dua akar: (1) builder menu menyembunyikan grup bila ID grup tidak ada di
  izin peran (grup `akuntansi` tidak dimiliki modul mana pun); (2) katalog modul basi.
  Analisis otomatis katalog ↔ menu menemukan: `rfid` = ID tak dikenal (hub sebenarnya `rfid-hub`);
  tab Barang Masuk/Keluar tanpa pemilik modul; Posting Gagal tanpa pemilik; hub Operasi Gudang
  diberikan ke inventory/QC/MD Quality tanpa satu pun tab tampaknya; hub Hutang diberikan ke
  Pembelian/Interco tanpa tabnya; `cs-bi-sales/stock` sudah tidak ada.
- **Perubahan perilaku:**
  - Builder (`navigationConfig.buildNavGroups`): untuk **peran kustom & pratinjau editor peran**, grup

    "tidak ada"); anak tetap disaring satu per satu. **Peran bawaan tidak memakai aturan ini** (rancangan
    `roles` grup + overlay tetap) — dicek dengan membandingkan menu 13 peran bawaan sebelum/sesudah.
  - Item hub yang semua tab tampaknya tidak terlihat oleh peran tidak lagi ditampilkan (pintu mati —
    view hub tidak punya renderer). Dampak pada peran bawaan, **satu-satunya perbedaan menu bawaan**:
    `md`, `md_quality`, `sample_admin` kehilangan "Operasi Gudang"; `sample_admin` kehilangan
    "Pesanan" — keduanya sebelumnya membuka halaman kosong.
  - Katalog (`backend/access_modules.py`): Operasi Gudang + `goods-receipts`, `wms-outbound`, `rfid-hub`
    (ganti `rfid`); inventory + `operations`; QC & MD Quality + `qc-inspection`; Akuntansi +
    `posting-failures`; Pembelian & Interco tanpa `accounts-payable`; buang `cs-bi-sales/stock`.
    Daftar menu peran kustom dihitung ulang dari katalog saat registri disinkronkan
    (`role_registry.py:270`), jadi peran kustom lama ikut terkoreksi tanpa disimpan ulang.
- **Bukti:**

## FE-04 — Tombol/petugas dibatasi nama role meski izin efektif berbeda
- **Berlaku di HEAD:** ya (dicocokkan dengan `permissions_config.py` & izin tiap endpoint).
- **Perubahan perilaku** — tombol memakai `can(user.permissions, resource, action)` = izin yang sama
  dengan endpoint (satu izin per aksi, tidak digabung):

  | Layar | Sebelum | Sesudah (= server) |
  |---|---|---|
  | Pesanan Khusus — Buat | admin/sales/manager | `order.create` |
  | Detail OD — ACC · status · ajukan draf · item/redesign · referensi · teruskan · ACC pelanggan | daftar peran | `order.approve` · `order.update` · `order.create` · `order.create` · `order.create` · `order.approve` · `order.update` |
  | Kunci harga OD | daftar peran (FE & BE) | `order.update` + peran pengunci **dengan peran acuan** (FE `roleIs` = BE `role_in`) — aturan peran tetap |
  | Realisasi pengadaan OD | daftar peran | `purchase_requisition.create` + `od_fulfillment.realize` |
  | Retur — ACC/settle/pembalikan · Tolak | admin/manager · **status saja** | `sales_return.approve` · `sales_return.reject` |
  | SPK inspeksi — buat · tugaskan · putuskan | admin/manager | `inspection.create` · `.assign` · `.decide` |
  | GRN — buat · review · hitung · tutup | daftar peran (tutup = review) | `goods_receipt.create` · `.review` · `.count` · `.close` |
  | Transfer — Setujui / Tolak | hanya `manager` | `transfer.approve` / `transfer.reject` (dipisah) |
  | Selisih pembayaran — putuskan/anulir | admin/manager/**sales** | `payment_variance.decide` (Finance dapat; Sales tidak) |
  | Saldo pelanggan — penyesuaian | admin/manager | `ar_receipt.void` |
  | Badan usaha · peran · akun | `role === "admin"` | `entity.create/update` · `permission.update` · `user.create/update/delete` |
  | Lokasi & penempatan / penerimaan transfer (supervisor) | literal | `roleIs` (peran acuan dikenali) = `placement_rules.is_supervisor` |

  Status dokumen, scope, approval bertingkat, dan larangan Admin sebagai acuan tidak diubah; server
  tetap penegak utama.
- **Petugas inspeksi (backend):** daftar & validasi penugasan = akun **aktif** yang perannya (termasuk
  kustom) punya `inspection/qc/md_quality.inspect` **dan** ditugaskan di badan usaha dokumen
  (`allowed_entities_for`). Penugasan akun tak berwenang → 400 dari server.
- **Bukti:** pytest `test_fe04_fe05_access.py` **6/6** (HTTP, peran & akun uji dibuat/dihapus lewat API):
  petugas kustom QC muncul, akun di PT lain & Finance tidak; menugaskan Finance → 400; kunci harga:
  turunan Sales lolos gerbang peran, Finance 403; izin efektif `/auth/me` berubah segera setelah
  tingkat modul diturunkan dan `POST /goods-receipts` lalu 403. Jest render (react-dom/server):
  `TransferDetailModal` 3 skenario (admin berizin, kustom approve-saja, manager dicabut),
  Pesanan Khusus (kustom `order.create` ya, manager view-only tidak).

## FE-05 — Data Gudang menolak Admin Gudang yang berizin
- **Berlaku di HEAD:** ya — direproduksi: `whadmin@` `GET /warehouses?scope=all` → 403.
- **Perubahan perilaku:** halaman meminta `scope=all` hanya untuk peran master (admin/manager/warehouse,
  peran acuan dikenali — FE `roleIs` = BE `role_in`); peran lain memuat daftar bawaan = gudang yang
  boleh dipakai PT aktif (scope sah server, tidak dibuka seluruhnya). Pilihan "Semua gudang"
  disembunyikan untuk non-master. Tombol buat/ubah/nonaktif per `warehouse.create/update/delete`.
- **Bukti:** browser sebagai `whadmin@` → Data Gudang terisi, tanpa pesan tolak, tanpa filter
  "Semua gudang", tombol buat gudang tampil; jaringan: `GET /api/warehouses` (tanpa `scope=all`).
  pytest: Admin Gudang daftar 200 & `scope=all` tetap 403; turunan Manager `scope=all` 200.
  Jest: Admin Gudang berizin → tombol buat ada, filter "all" tidak; Manager view-only → tanpa tombol buat.
