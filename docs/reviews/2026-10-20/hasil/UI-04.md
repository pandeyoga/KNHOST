## FE-06 — Harga Khusus dari Meja Saya membuka target yang salah
- **Berlaku di HEAD:** ya — `ROLE_DESK_TARGET.price_approval` = `view: "approvals"`; `AppViewRouter` hanya
  punya `price-approvals`. Layar `PriceApprovals` juga tidak menerima fokus dokumen.
- **Perubahan perilaku:**
  - Target → `view: "price-approvals"`, `nav_id: "approval-inbox"` (tab "Pengajuan Harga Khusus" hub
    Persetujuan) dengan `focus_id` pengajuan.
  - Layar mengambil pengajuan lewat `GET /price-approvals/{id}` (akses & scope diperiksa server), menampilkan
    **hanya pengajuan asal** + banner "dibuka dari antrean" + tombol "Tampilkan semua". Dokumen hilang/di luar
    akses → pesan jelas, tidak berpura-pura berhasil.
  - Ditemukan saat perbaikan: tombol Setujui/Tolak/Akhiri masih memakai nama peran (`role` lokal, lolos dari
    pola grep sisir ROLE-01). Kini setujui & akhiri = `price_approval.approve`, tolak = `price_approval.reject`.
  - Guardrail baru `scripts/guardrails/verify_desk_targets.py` (didaftarkan di `gate.sh`): **28 target**
    antrean (meja per peran, baris, Finance, gudang, alamat dokumen) wajib menunjuk view yang dirender.
- **Bukti:**
  - Jest `fe06PriceFocus.test.js` **4/4**: tautan → `price-approvals` + ID; fokus menampilkan pengajuan asal
    saja + fokus dilepas; 404 → pesan; tombol Setujui ikut izin. **Bukti-merah:** 4/4 gagal di kode lama.
  - Guardrail: kode lama **1 temuan** (`ROLE_DESK_TARGET.price_approval -> view 'approvals'`), sesudah 0.
  - Browser (Manager demo, pengajuan uji dibuat Sales lewat API dengan lampiran bukti, dihapus sesudahnya):
    Meja Saya → Permintaan harga khusus → **Putuskan** → URL `?view=price-approvals`, tab "Pengajuan Harga
    Khusus" aktif, hanya kartu pengajuan itu dengan tombol Setujui/Tolak. Sebelumnya `?view=approvals` kosong.

## FE-07 — Error aksi retur tidak terlihat; modal menutup saat gagal
- **Berlaku di HEAD:** ya — handler di `SalesReturns` menangkap error ke state induk; cabang detail tidak
  menerimanya; `ReturnSettleModal` menutup setelah `await onSettle` walau gagal; modal tolak menutup seketika.
- **Perubahan perilaku:** satu pintu aksi (`runAction`) untuk submit/approve/mulai & simpan inspeksi/settle/
  tolak/buang draf: error tampil di **detail yang sedang terbuka** (`return-action-error`), handler mengembalikan
  pesan sehingga **modal tolak & penyelesaian tetap terbuka dengan pesan & input**; **klik ulang selama proses
  diabaikan** (ref, bukan state) dan tombol aksi dinonaktifkan; error dibersihkan saat kembali ke daftar.
  "Buang draf" memakai dialog aplikasi (`askConfirm`), bukan `window.confirm`.
- **Bukti:** jest `fe07ReturnErrors.test.js` **4/4** (approve 409 → pesan di detail; klik ganda → 1 POST;
  tolak 403 → modal + alasan tetap + pesan; settle gagal → modal terbuka dengan pesan, berhasil → tertutup).
  **Bukti-merah:** 4/4 gagal di kode lama. Guardrail dialog bawaan: 4 → 3 pelanggaran (sisanya di luar UI-04).
- **Status:** implemented_pending_review

## FE-09 — Pemilih SO retur diam-diam terbatas 200 pesanan
- **Berlaku di HEAD:** ya — `GET /sales-orders` tanpa paginasi = 200 terbaru, lalu disaring di peramban.
- **Perubahan perilaku:**
  - Endpoint baru `GET /sales-returns/eligible-orders` (izin = membuat retur): SO dalam scope pengguna (sama
    dengan daftar SO: badan usaha, kepemilikan sales, pagar lini) yang **masih punya barang terkirim lewat
    Surat Jalan belum habis diklaim retur aktif** (dasar sama dengan `/returnable`), cari `?q=` nomor/pelanggan,
    `?page=&page_size=` (tidak menaikkan batas, tidak mengunduh semua).
  - Form retur desktop & HP: kotak cari + daftar hasil + "Muat lagi" + keterangan "x dari y pesanan yang masih
    punya barang terkirim untuk diretur". Sumber 200-SO lama dibuang dari kedua pemanggil.
- **Bukti:**
  - pytest `test_fe09_return_eligible_orders.py` **4/4**: 201 SO draf baru (fixture, dibersihkan) → sumber lama
    200 baris tanpa SO terkirim, endpoint baru menemukannya via nomor; draf tidak pernah ditawarkan; paginasi
    tanpa tumpang tindih & cari nama pelanggan; SO yang klaimnya menghabiskan barang terkirim tidak ditawarkan
    lalu tersedia lagi saat klaim dilepas; Finance 403. **Bukti-merah:** 4/4 gagal di kode lama.
  - Jest: opsi dari server, "Muat lagi" menambah halaman 2, pencarian dikirim sebagai `q`, tidak memanggil
    `/sales-orders`. **Bukti-merah:** gagal di kode lama.
  - Browser (Manager): Buat Retur → kotak cari + "5 dari 5 pesanan yang masih punya barang terkirim untuk
    diretur" (PT aktif; 7 SO punya Surat Jalan di semua PT). Form ditutup tanpa menyimpan.
- **Status:** implemented_pending_review
