# P08 — Keputusan pemilik untuk W2-REQ-01 s/d 09

Tanggal: 2026-10-04. Sumber: memo25, register26, prompt27. Keputusan ini menjadi kontrak bisnis untuk implementasi P08. Status tracker tetap `open` sampai implementasi + bukti tersedia.

W2-025 (pagar lini R&D di detail/patch/turunan) dikerjakan lebih dulu sebagai defect, tanpa keputusan tambahan.

| ID | Keputusan | Aturan yang ditetapkan | Acceptance utama |
|---|---|---|---|
| W2-REQ-01a | Field pelaksana wajib | Submit hasil round menyimpan `recorded_by` (akun penginput, otomatis) dan `performed_by_user_id`/`performed_by` (wajib dipilih dari daftar user aktif entitas). Data lama: `performed_by` lama dipertahankan sebagai recorded_by. | Wiwi menginput untuk Tita → recorded_by=Wiwi, performed_by=Tita; tanpa pelaksana → 422; histori/timeline/modal histori menampilkan keduanya. |
| W2-REQ-01b | Tanpa izin per jenis uji | Cukup pemisahan lini + izin aksi modul (`rnd.submit/assess/decide`). Tidak menambah permission per jenis sampling. | Dokumentasikan; tidak ada perubahan permission. |
| W2-REQ-02 | Tata kelola + migrasi massal dengan rollback | SKU stabil (koreksi nama tanpa SKU baru, histori nama tercatat). stage/fabric_type/line_code/warna internal adalah atribut terpisah dan wajib menurut stage. Supplier color/lot tetap tersimpan; lot internal tidak di-rename. Layar preview legacy: daftar atribut kosong/tidak kanonik, kandidat duplikasi, konflik. Eksekusi massal hanya dari preview yang disetujui, dengan batch id, snapshot sebelum, jejak perubahan dan rollback per batch. Standar penamaan perusahaan TIDAK dikarang; aturan duplikasi hanya pada atribut kanonik. Alias kode warna customer belum ditetapkan (ditunda). | Preview tidak mengubah data; apply batch → rollback mengembalikan snapshot persis; SKU & referensi roll/dokumen tidak berubah. |
| W2-REQ-03 | Peringatan (warn), bukan blokir | Uji wajib per lini: woven/knit = labdip+handfeel; printing = proofing (+handfeel bila spesifikasi mewajibkan). Keputusan sample, approve_spec dan release mengecek kelengkapan ACC; bila kurang → tetap diizinkan, tetapi wajib alasan override dan tercatat (siapa, kapan, uji yang kurang) di timeline/audit. Bahan standar (create product langsung) tidak terkena. Retry pembentukan SKU tidak membuat master ganda. | Kurang uji tanpa alasan → 422; dengan alasan → sukses + catatan warning; semua ACC → tanpa warning; bahan standar tanpa R&D tetap bisa dibuat. |
| W2-REQ-04 | Angka utama = total grup | Board sales: angka utama available/reserved/incoming grup dari `global_total`, tanpa nama/rincian owner dan biaya. Baris terpisah "siap dijanjikan dari entitas saya". Alokasi tetap per owner + interco. | Role sales tidak menerima owner/biaya di payload; stok yang sama tidak dihitung dua kali; ATP diberi label sesuai definisi (available+incoming). |
| W2-REQ-05 | Tetap entitas aktif + ganti cepat | PO tetap dibuat pada entitas aktif. Form PO/realisasi PR menampilkan entitas pembeli dengan jelas dan tombol cepat ganti entitas (hanya entitas yang diizinkan), tanpa kehilangan draft/konteks SO-PR. | Ganti entitas dari form → PO tercipta di entitas yang dipilih; entitas tak berizin tidak muncul; backend tetap memakai active_entity_id. |
| W2-REQ-06 | Tugas keputusan MD | Saat GRN menghasilkan selisih di luar toleransi, sistem membuat tugas untuk MD penanggung jawab PO (fallback: pembuat PO) dengan pilihan: tunggu sisa / amendment ke qty aktual / short-close; alasan wajib; jejak approval. Nilai PO, tagihan, DP tidak diubah otomatis. Bila PO sudah ada DP/pembayaran/tagihan → notifikasi Finance. Amendment harus sebelum short-close. Idempoten saat retry. | Kasus PO 10×100 terima 960: (a) tunggu → remainder tetap; (b) amendment → nilai PO baru via approval; (c) short-close → status closed_short, nilai tidak berubah. Tabel sebelum/sesudah qty/total/received/tagihan/bayar/saldo/jurnal. |
| W2-REQ-07 | Reservasi sejak keputusan fulfillment/PR disetujui | Saat keputusan fulfillment SO jalur makloon atau PR makloon disetujui, bahan input dicadangkan menurut resep/yield/satuan (bukan 1:1 otomatis), terikat ke SO/PR, lalu dipindah ke MKO saat realisasi. Reservasi mengurangi available untuk komitmen baru, tidak mengurangi fisik/tanpa jurnal. Issue mengonsumsi reservasi yang sama. Cancel/replan PR/MKO/SO melepas/menyesuaikan. Shortage parsial dicatat sebagai kekurangan, bukan reservasi negatif. | Dua SO bersamaan tidak memakai bahan yang sama; cancel melepas; issue tidak double-consume; rekonsiliasi available/reserved/subcon/WIP cocok. |
| W2-REQ-08 | Tag wajib + pengecualian berizin; SJ per gudang | Putaway, staging cross-dock, loading check dan dispatch menolak roll tanpa tag terverifikasi. Pengecualian hanya untuk permission khusus dengan alasan, tercatat di audit. Source SO tidak membebaskan GRN/QC/owner. SJ dibuat per shipment per gudang sesuai muatan nyata; ringkasan SO tidak dipakai sebagai bukti berangkat. Tautkan RFID-03 lama. | Roll tanpa tag ditolak di keempat titik; pengecualian tanpa izin → 403, dengan izin + alasan → lolos + audit; SO 3 gudang → 3 SJ sesuai muatan. |
| W2-REQ-09 | FEFO + konfirmasi pembulatan + potong berizin | Urutan tetap prefix FEFO (900 atau 905 sesuai urutan, tidak hard-code). Total roll/panjang/delta selalu tampil; finalisasi wajib pilihan eksplisit pengguna (naik/turun/exact). Opsi `exact_cut` hanya untuk permission khusus. Satuan yard/meter memakai konversi resmi. | 9×100+1×105 dua urutan → hasil sesuai urutan; tanpa pilihan → ditolak; exact_cut tanpa izin → 403; qty invoice mengikuti hasil final. |
