## Tujuan

Empat kejadian yang hari ini membuat nilai roll berbeda dari akun persediaan dibuat sejalan: roll yang di-scrap tidak
lagi bernilai; retur ke pemasok mengeluarkan persediaan sebesar nilai buku rollnya; HPP surat jalan memakai biaya tiap
roll apa adanya dan roll berbiaya 0 bisa dilihat daftarnya; barang retur pelanggan masuk lagi sebesar HPP saat dijual.

### Server

**1. Scrap (IV-02)** — `release_quarantine`: untuk roll ber-aksi `scrap` yang jurnal hapus-bukunya ada (baru terbit
atau sudah ada), tulisan roll yang sama menambah `writeoff_unit_cost`, `writeoff_base_unit_cost` dan menyetel
`unit_cost = 0`, `base_unit_cost = 0`; `roll_cost_history.record(...)` dengan alasan baru `scrap_writeoff`
("Dihapus-buku (scrap) — nilai roll menjadi 0"). `reverse_writeoff`: memulihkan kedua biaya dari field simpanan
(alasan `scrap_writeoff_reversal`, "Scrap dibatalkan — biaya roll dipulihkan").

**2. Retur beli (IV-06).**

- `_consume_return_rolls`: tiap unsur `effects` mendapat `unit_cost` (biaya roll: `unit_cost` atau `base_unit_cost`)
  dan `value_sen = to_cents(qty × unit_cost)`.
- `_finalize_supplier_return_financials`: `book_value = from_cents(Σ value_sen)` dan `book_value_rolls` ditulis pada
  tulisan `stock_adjusted: true`. Panggilan ulang (stok sudah disesuaikan) membaca nilai tersimpan.
- `post_purchase_return(ret, *, amount, ppn=0.0, label="", outcome="ap_credit", cash_account_code="", book_value=None)`.
  Dengan `D = amount − ppn` (nilai nota tanpa PPN), `B = book_value`, `selisih = B − D`:

| Keadaan | Baris jurnal (`source_type="purchase_return"`, tidak berubah) |
|---|---|
| `book_value` kosong (retur lama) atau `abs(selisih)` ≤ 0,005 | Seperti sekarang: Dr hutang/GR-IR/kas `amount`; Cr persediaan `D`; Cr PPN masukan `ppn` |
| `selisih` > 0 dan kunci terpetakan | Dr hutang/GR-IR/kas `amount`; Dr `retur.selisih_retur_beli` `selisih`; Cr persediaan `B`; Cr PPN masukan `ppn` |
| `selisih` < 0 dan kunci terpetakan | Dr hutang/GR-IR/kas `amount`; Cr persediaan `B`; Cr PPN masukan `ppn`; Cr `retur.selisih_retur_beli` `−selisih` |
| `selisih` ≠ 0 dan kunci belum terpetakan untuk PT itu | Perilaku hari ini (Cr persediaan `D`); `book_value_diff = selisih`, `book_value_posted = false` |

  Pada tiga baris pertama `book_value_diff = selisih` dan `book_value_posted = true`.

**3. HPP surat jalan (IV-07)** — `post_shipment_cogs`: bila `shipment.rolls` berisi, HPP = Σ `extended_cost` (atau
`unit_cost × length` bila field itu tidak ada) atas **semua** roll, termasuk yang berbiaya 0. Jalur rata-rata hanya
untuk surat jalan lama tanpa potret. HPP 0 → tidak ada jurnal (seperti sekarang).

**4. Daftar biaya 0** — endpoint baru:

| | |
|---|---|
| Metode · path | `GET /api/gl/zero-cost-rolls` |
| Izin | `accounting.view` |
| Parameter | `page` (bawaan 1), `page_size` (bawaan 50, maks 200); PT dari konteks (`resolve_requested_entity`), mode "Semua PT" → semua PT dalam cakupan pengguna |
| Jawaban | `{"in_stock": {"items": [{roll_id, roll_no, product_name, entity_id, length_remaining, status}], "total"}, "shipped": {"items": [{shipment_no, order_number, roll_no, length, shipped_at, entity_id}], "total"}, "page", "page_size"}` |
| Isi | `in_stock`: roll berstatus `OWNED_ROLL_STATUSES`, sisa > 0, `unit_cost` dan `base_unit_cost` 0/kosong, **tanpa** `writeoff_je_id` aktif. `shipped`: baris `shipments.rolls[]` ber-`unit_cost` 0 pada surat jalan tidak batal |

**5. Retur jual (IV-08)** — fungsi baru di `backend/services/return_service.py`:
`async def return_unit_cost(ret: dict, item: dict, roll_id: str = "") -> Tuple[float, float, str]` mengembalikan
`(biaya, biaya_dasar, sumber)`:

1. `surat_jalan` — roll yang dikembalikan (`roll_id`, atau semua `item["roll_ids"]`) ditemukan di `shipments.rolls[]`
   surat jalan tidak batal milik pesanan itu → biaya = rata-rata potret `unit_cost` tertimbang panjang yang
   dikembalikan (`item["roll_qtys"]`, atau panjang potret).
2. `rata_surat_jalan` — tidak ada `roll_ids`, tetapi pesanan punya potret untuk produk itu → Σ `extended_cost` ÷ Σ
   `length` produk itu.
3. `wac` — selain itu, rata-rata tertimbang produk seperti sekarang.

`biaya_dasar` = `base_unit_cost` dokumen roll asal bila ada dan ≤ biaya; selain itu = biaya. Kondisi `damaged` tetap 0.
Dipakai di tiga tempat: `_cn_figures` (HPP balik), `_restock_returned_items` (biaya roll masuk), dan
`return_roll_settlement_service.plan_event` (per roll). `gl_service._avg_unit_cost` tidak lagi dipanggil dari retur.

**6. Invarian** (`02` D2) di `scripts/verify_data_integrity.py` (`layer_gl_invariants`): `GL-SCRAP` (WARN) — jumlah
roll `damaged` ber-`writeoff_je_id` yang belum dibalik dan bernilai > 0 harus 0.

## Di luar lingkup

- Penanda gagal untuk jurnal scrap retur dan potong uji mutu (`post_durable`) → tercatat di garis dasar penjaga PK-18
  tanpa unit pemilik; unit ini tidak mengubahnya.
- Selisih harga faktur terhadap PO dan jumlah boleh-tagih setelah retur → PK-28.
- Batas total nota kredit dan nilai efektif setelah koreksi harga → PK-32.
- Menjalankan skrip migrasi pada data nyata → keputusan pemilik (H3).
- Mengisi biaya roll yang 0 → koreksi data, bukan unit ini; daftar di butir 4 hanya menampilkannya.

## Asumsi dan risiko

- `ASUMSI:` roll yang di-scrap tetap ada secara fisik (status `damaged`), jadi yang dinolkan biayanya, bukan panjangnya.
- `ASUMSI:` selama akun selisih retur beli belum dipetakan, perilaku hari ini dipertahankan dan selisihnya tampil di
  rincian retur (`00` §4.1 butir 2).
- `ASUMSI:` roll yang diretur pelanggan dinilai pada potret biaya saat kirim walau landed cost roll itu bertambah
  sesudahnya (tambahan itu sudah dibebankan lewat PK-26).
- `RISIKO:` registri pemetaan belum pernah punya kunci ber-`default` kosong. Bila ada uji atau penjaga yang mewajibkan
  `default` terisi, perluas pemeriksaannya agar menerima kunci `required` tanpa bawaan dan laporkan. Membatalkan: hapus
  kunci; `post_purchase_return` tanpa `book_value` kembali ke jurnal lama.
- `RISIKO:` HPP surat jalan yang memuat roll berbiaya 0 kini lebih kecil dari sebelumnya; laba kotor naik sampai biaya
  roll itu diperbaiki. Daftar "Roll berbiaya 0" adalah alat menemukannya.
