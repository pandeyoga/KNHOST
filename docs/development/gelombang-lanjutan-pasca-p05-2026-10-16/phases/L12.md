## Sasaran, dependensi dan navigasi

Buktikan kontrak ERP benar-benar mendukung UR300, C72 dan CP30EN serta konsisten dengan dokumentasi middleware terpisah.

Prasyarat validasi penuh: L01, L04, L07, L10. Bagian independen dapat dipersiapkan sebelum semua prasyarat tervalidasi; catat kesiapan dan jangan menutup fase lebih awal.

Navigasi target: Pengaturan Perangkat → Profile/Health; Gudang → Tugas Handheld/Print Job/Gate Session; Monitoring → Retry/Reconcile.

Flow: Registry/profile → task/context → print/encode/verify → C72 workflow → UR300 observation/session → keputusan ERP → ACK/reconcile.

Navigasi di atas adalah rancangan konteks tugas. Cocokkan nama menu/route pada HEAD aktual; jangan mengaku menu target sudah tersedia. Saat menyerahkan hasil, berikan navigasi aktual dan langkah input → proses → output yang diuji.

## LN-121 — UR300/C72: durability, context dan keputusan bisnis

UR300 mengirim observation/session dalam event time dengan live/backfill, direction, reader context dan dedup. Gate decision ERP bukan sekadar read tag; delayed batch tidak boleh membuka gate saat ini. C72 menjalankan task source roll/bin/receipt/putaway/transfer/opname/loading dengan paging, progress dan completion sah. ACK harus sesudah durable commit; offline replay tidak menggandakan stok atau approvals.

Pending terkait: HW-01

- **LN-121-T01** — Diberikan batch offline dikirim ulang setelah restart, ketika ERP ACK dan process, maka tidak hilang event dan tidak double posting; keputusan gate tidak dijalankan berdasarkan bacaan lama.

## LN-122 — CP30EN print/encode/verify dan reprint yang aman

Stable job ID, lease/claim/renew, start barrier, item outcome success/failed/unknown/partial, ACK durable dan reconcile harus dipisah. Retry jaringan tidak berarti cetak fisik ulang. Reprint teks qty memakai EPC sama; retag/replacement-tag tindakan tersendiri dan menonaktifkan tag lama sesuai prosedur. Dukungan encoding command/media/antenna/printer SDK harus diuji CP30EN aktual; jangan menyimpulkan kompatibel hanya dari contoh ZPL.

Pending terkait: HW-01

## Prompt pelaksanaan fase

Kerjakan requirement fase L12 di atas. Baca AGENT_GUIDE, keputusan aktif dan sumber terkait pada COVERAGE. Periksa code, UI dan flow existing terlebih dahulu. Untuk tiap requirement, jelaskan sebelum/sesudah, API/schema/migrasi terdampak, sumber data dan efek lintas modul. Jalankan acceptance dengan input serta hasil aktual, bukan mengganti skenario menjadi test yang hanya mencerminkan implementasi. Sertakan error path, retry dan concurrency yang memengaruhi saldo/approval. Jalankan pemeriksaan repo yang diwajibkan sesuai perubahan.
