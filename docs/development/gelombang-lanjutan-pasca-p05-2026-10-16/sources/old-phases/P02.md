# P02 — Alamat, putaway, integritas referensi, dan rules WMS

**Kebutuhan:** IMP-22, IMP-23, IMP-24, IMP-25  
**Dependensi:** P01  
**Ukuran relatif:** XL  
**Status awal:** not_started

## Tujuan

Membenahi fondasi WMS sehingga setiap penempatan memakai alamat, status, owner, serta rules yang benar.

## Pekerjaan server dan kontrak

- [ ] Satukan resolver alamat modern/legacy untuk editor, scan penerimaan, putaway manual, PA, transfer, dan reporting. Pertahankan ID node ketika nama berubah.
- [ ] Validasi pohon lokasi, parent, ID unik, penghapusan, dan perpindahan node. Stok/tugas beralamat lama tidak boleh orphan secara diam-diam.
- [ ] Buat evaluator kelayakan bersama: scope lokasi, gudang aktif, owner shared/dedicated, fungsi area, atribut produk, kualitas, komitmen roll, dan kapasitas.
- [ ] Definisikan pewarisan rules dan AND untuk constraint yang sama-sama diwajibkan. Bedakan rekomendasi, batas keras, peringatan, dan pengecualian berizin.
- [ ] Terapkan matriks status putaway. Tolak in-transit/offsite/consumed dari penempatan stok fisik; area QC/hold mengikuti SOP.
- [ ] Validasi ulang saat mutasi dan gunakan mekanisme atomik/idempotensi yang cocok dengan database aktual agar dua petugas tidak melewati kapasitas atau menempatkan roll bersamaan.
- [ ] Perbaiki DEV-F03 sejak fondasi: occupancy membawa unit/dimensi, subtotal tidak mencampur meter dengan kg, utilization memakai kapasitas yang sepadan. Hapus label meter tetap pada consumer lokasi existing; dashboard hierarchy lengkap dilanjutkan P08.

## Pekerjaan antarmuka

- [ ] Pastikan menu putaway dan custom role berfungsi; antrean menunjukkan siap/terhambat beserta alasan.
- [ ] Tampilkan tree Lokasi > Gudang > Zona > Lemari > Rak > Bin dengan padanan Rack/Level yang konsisten.
- [ ] Sediakan alamat lengkap, scan label, rules efektif, isi roll, kapasitas berdimensi, serta rekomendasi tujuan yang valid.
- [ ] Sediakan daftar orphan dan koreksi alamat berjejak; rekomendasi bukan pengganti validasi server.

## Data lama dan migrasi

- [ ] Adapter struktur legacy harus mempertahankan node/bin yang masih direferensikan. Migrasi versi skema menggunakan dry-run, mapping ID, dan rerun yang tidak menggandakan node.
- [ ] Alamat orphan masuk exception; jangan memindahkan barang fisik berdasarkan asumsi.
- [ ] Rules/kapasitas belum dikonfigurasi tidak diberi angka atau batas bisnis fiktif. Tentukan perilaku compatibility sebelum aktivasi.
