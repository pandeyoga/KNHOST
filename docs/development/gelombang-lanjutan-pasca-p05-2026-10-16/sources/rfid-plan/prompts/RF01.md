# RF01 — API ERP dan fondasi middleware

**Kebutuhan:** RFID-02, RFID-07, RFID-08, RFID-09  
**Dependensi:** RF00, P01

## Pekerjaan

- [ ] Dokumentasikan endpoint existing serta gap pada session metadata, limit/idempotensi, task discovery dan operator binding.
- [ ] Tetapkan kontrak source, event identity, ACK/result, error recovery, replay, version dan backwards compatibility. Tambah endpoint hanya jika flow existing belum menyediakan kontrak yang diperlukan.
- [ ] Bangun SDK adapter interface, transport, persistent outbox dan environment-specific profiles; hindari reader settings atau stock rules duplikat.
- [ ] Tambahkan health/queue/version monitoring dan operasi provisioning/rotation sesuai platform yang sudah digunakan.
- [ ] Terapkan role/site/warehouse/task checks untuk API operator dan device; event tidak dapat memindahkan stok dengan payload yang dipercaya begitu saja.
- [ ] Tinjau claim/lease/ACK printer dan kontrak item/attempt, partial output, error/uncertain outcome serta recovery efek on_printed; dokumentasikan perubahan API sebelum client printer mengandalkannya.

## Acceptance

RACC-03, RACC-04, RACC-07, RACC-12, RACC-14, RACC-15, RACC-16, RACC-17, RACC-18, RACC-22, RACC-26, RACC-28, RACC-29. Baca [matriks acceptance](../ACCEPTANCE_RFID.md).

**Gate:** Contract/API+DB tests dan recovery membuktikan dua jalur ingest serta identitas task/device; fondasi dipakai C72 dan gate.
