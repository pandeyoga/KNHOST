# P00 — Baseline, keputusan bisnis, dan kontrak antarmodul

**Kebutuhan:** Persiapan/validasi lintas seluruh IMP  
**Dependensi:** Tidak ada  
**Ukuran relatif:** M  
**Status awal:** not_started

## Tujuan

Menetapkan kondisi repo yang benar-benar akan dikembangkan dan kontrak bersama sebelum perubahan lintas modul.

## Pekerjaan server dan kontrak

- [ ] Catat branch/commit target, perubahan yang sudah ada, instruksi repo, runtime, kemampuan database, dan status deployment yang akan dipakai UAT. Jangan menganggap snapshot audit adalah versi terbaru.
- [ ] Reproduksi ulang DEV-F01–F05 dan verifikasi DEV-G01–G06 pada branch target. Catat sudah fixed, masih berlaku, berbeda perilaku, atau belum dapat diverifikasi; jangan menulis ulang perbaikan yang sudah benar.
- [ ] Inventaris sumber kebenaran untuk master, roll, owner, alamat, reservasi, dokumen pemenuhan, qty/satuan, status, dan absensi. Petakan semua consumer UI/API serta dokumen turunannya.
- [ ] Tetapkan kontrak ID baris SO/OD, hubungan supply-demand, perpindahan roll, penerimaan parsial, dan kamus metrik Keep/Pending/ATP. Tandai kontrak usulan dan keputusan bisnis secara terpisah.

## Pekerjaan antarmuka

- [ ] Petakan menu, peran standar/custom, desktop/mobile, meja pengguna, dan jalur drill-down. Buat matriks layar yang terdampak 35 kebutuhan.
- [ ] Siapkan contoh data UAT lintas entitas dan lokasi; rekam kondisi sebelum perubahan.

## Data lama dan migrasi

- [ ] Lakukan inventaris skema dan dry-run diagnosis data; tahap ini tidak mengubah stok, HPP, jurnal, atau data produksi.

## Keputusan terkait

DEC-01, DEC-02, DEC-03, DEC-04, DEC-05, DEC-06, DEC-07, DEC-08, DEC-09, DEC-10, DEC-11, DEC-12, DEC-13, DEC-14, DEC-15, DEC-16. Detail ada di [register keputusan](../DECISIONS.md). Menunggu satu keputusan hanya membatasi pekerjaan yang bergantung keputusan tersebut.

## Pengujian dan gate

Skenario: ACC-00. Baca expected result di [matriks penerimaan](../ACCEPTANCE_MATRIX.md).

**Gate:** Baseline commit, hasil reproduksi, matriks consumer, kontrak bersama, dan daftar keputusan mempunyai berkas bukti. Kegagalan baseline dipisahkan dari regresi baru.

## Prompt untuk agent development

Salin teks berikut atau minta agent membaca file fase ini beserta berkas rujukannya.

```text
1. Baca AGENT_GUIDE.md, DEVELOPMENT_PLAN.md, BACKLOG.json, DECISIONS.md, serta source requirement. Ikuti instruksi repo dan catat commit aktual.
2. Kerjakan fase P00 — Baseline, keputusan bisnis, dan kontrak antarmodul. Scope: Persiapan/validasi lintas seluruh IMP. Tujuan: Menetapkan kondisi repo yang benar-benar akan dikembangkan dan kontrak bersama sebelum perubahan lintas modul.
3. Verifikasi dependensi Tidak ada. Reproduksi gap pada branch aktual sebelum mengubah kode. Fase ini menghasilkan analisis implementasi yang konkret. Perubahan aplikasi hanya untuk diagnosis yang diperlukan; jangan melakukan refactor luas atau migrasi produksi. Mulai pencarian kompatibilitas mesin P09-A setelah baseline tersedia.
4. Laksanakan seluruh pekerjaan server, UI, data/compatibility, dan consumer pada rincian fase ini. Jangan menebak keputusan bisnis; catat DEC terkait dan lanjutkan bagian independen.
5. Jalankan skenario ACC-00 yang relevan pada lingkungan uji, ditambah regression meaningful yang diperlukan. Catat not_run/waiting dengan jujur; build saja tidak membuktikan flow.
6. Penuhi gate: Baseline commit, hasil reproduksi, matriks consumer, kontrak bersama, dan daftar keputusan mempunyai berkas bukti. Kegagalan baseline dipisahkan dari regresi baru.
7. Simpan laporan di evidence/P00/report.md menggunakan template. Perbarui BACKLOG.json dan render TRACKER.md. Jika baru implementasi dan tes developer, gunakan implemented_pending_validation; jangan menandai validated tanpa verifikasi.
8. Serahkan commit, perubahan perilaku, migrasi, hasil tes/input-output/UI, issue terbuka, dan status setiap IMP. Jangan membeli perangkat, menghubungi pihak luar, atau deploy produksi otomatis.
```

Gunakan [template laporan](../templates/PHASE_REPORT.md). Status dan bukti dicatat dalam [BACKLOG.json](../BACKLOG.json).
