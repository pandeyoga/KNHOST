# P08 — Opname, dashboard stok, dan konsistensi meja pengguna

**Kebutuhan:** IMP-01, IMP-28, IMP-29  
**Dependensi:** P01, P02, P03, P04, P05, P06, P07  
**Ukuran relatif:** XL  
**Status awal:** not_started

## Tujuan

Menyatukan hasil fisik, penyesuaian, analitik lokasi, dan detail pekerjaan setelah alur transaksi stabil.

## Pekerjaan server dan kontrak

- [ ] Scope opname dari tree diterjemahkan ke bin/owner tanpa overlap. Snapshot, perubahan selama hitung, approve, actual roll, dan exception mengikuti SOP.
- [ ] Bedakan koreksi alamat, qty hilang/lebih, salah unit, dan masalah tag. Hubungkan sweep RFID ke satu kasus penyesuaian, bukan posting kedua.
- [ ] Jaga adjustment dan jurnal sekali saja, reservasi terdampak, valuasi, reversal, dan jejak persetujuan.
- [ ] Agregasikan stok lokasi dari roll/proyeksi sah menurut unit/status/owner; jangan menjumlahkan unit beda atau paginated rows sebagai total.
- [ ] Sediakan subtotal seluruh node, unassigned, orphan, kapasitas berdimensi, dan rekonsiliasi anak-induk.
- [ ] Standarkan summary-detail untuk meja seluruh peran; query/filter/scope ringkasan sama dengan detail pembentuknya.

## Pekerjaan antarmuka

- [ ] Opname memakai tree/scan dan daftar actual roll, review selisih, approve, serta tindak lanjut reservasi/tag.
- [ ] Dashboard drill-down site > warehouse > zone > lemari > rak > bin/roll; status dan satuan eksplisit.
- [ ] Semua antrean peran membuka detail relevan dan mempertahankan filter saat kembali; siapkan empty/error/loading state desktop/mobile.

## Data lama dan migrasi

- [ ] Rebuild proyeksi/agregat melalui rekonsiliasi; tidak memperbaiki selisih dengan menimpa jumlah agar terlihat cocok.
- [ ] Count session aktif tidak diubah expected-nya diam-diam; strategi adaptasi dibuktikan. Histori adjustment/jurnal dipertahankan.
- [ ] Invalid-bin lama masuk orphan queue; jangan dihilangkan dari angka fisik.
