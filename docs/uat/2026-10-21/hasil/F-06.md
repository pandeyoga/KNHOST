## Perubahan perilaku (sebelum → sesudah)
1. **POD menutup SO otomatis.** Layanan baru `services/so_delivery_service.py`: sesudah transisi Logistik
   *Terkirim* / *Selesai* dan sesudah **serah terima ambil sendiri** (kode pickup), untuk setiap SO di pengiriman itu:
   bila SO `shipped` (terkirim penuh) dan **semua** Surat Jalan aktifnya ber-POD (`logistics_status`
   delivered/completed) → SO `done` lewat transisi yang sama dengan tombol manual (`so_transition`), aktor = petugas
   POD, `delivered_via: "pod"`, `delivered_by`, roll `in_transit_sales` → `delivered`, audit `order_delivered`
   (`via: pod_auto`), hook Pesanan Khusus tetap dipanggil. Idempoten & aman balapan (409 transisi = sudah ditutup
   jalur lain → diabaikan). Galat penutupan tidak pernah menggagalkan transisi logistiknya.
2. **SJ yang belum ber-POD menahan penutupan** — kirim sebagian: SJ pertama ber-POD → SO tetap *Dikirim*; SJ terakhir
   ber-POD → *Selesai*.
3. **Jelas di layar.**
   * Detail SO berstatus *Dikirim*: catatan **"Bukti terima (POD): x dari y Surat Jalan. Pesanan tertutup otomatis saat
     semua Surat Jalan ber-POD di Logistik. Belum: SJ-…"** (`GET /api/sales-orders/{id}/pod-progress`).
   * Pelacak SO (semua meja): tahap **"Bukti terima (POD) semua Surat Jalan — SO tertutup otomatis"** — oleh Logistik /
     Admin Gudang, tombol **Catat POD** kini membuka **Logistik tersaring nomor SO** (dulu tahap ini bernama
     "Dikonfirmasi diterima pelanggan" dan tombolnya membuka Barang Keluar, tempat POD tidak bisa dicatat).
   * Tombol manual **Tandai Diterima (Selesai)** tetap ada untuk SO tanpa alur Logistik.

Berkas: `backend/services/so_delivery_service.py` (baru), `services/logistics_service.py` (hook),
`routers/sales_orders_extra.py` (`pod-progress`), `services/so_tracker_service.py`; frontend
`features/orders/PodProgressNote.jsx` (baru), `features/orders/OrderDetailPanel.jsx`,
`features/sales_admin/workDeskApi.js` (`soTrackerLink`), `App.js` (`openDocument` meneruskan saringan Logistik).
