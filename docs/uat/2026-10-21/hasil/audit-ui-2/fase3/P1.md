### 2.1 Alias & preset (pola "gabung")
* **Registri** `config/viewAliases.js` (milik P2 selama fase paralel; P8 mengaktifkan tabel §6):
  ```js
  VIEW_ALIASES["my-approvals"] = { to: "approval-inbox", nav: "approval-inbox", preset: { tab: "matrix" },
                                   label: "Persetujuan Saya", since: "D-06" };   // legacy:true = nama tanpa layar
  resolveAlias(view) → { from, to, nav, preset, label, since, legacy } | null
  aliasTarget(view) · aliasesOf(view) · listAliases()
  ```
  Semua jalan masuk sudah lewat registri: sidebar/palet/deep link (`resolveDeepLinkTarget` — alias LEBIH DULU, peran
  divalidasi terhadap layar utama; bila tak berwenang → id lama diproses seperti dulu; id lama yang disembunyikan
  peran (`ROLE_NAV.remove`/`hidden_views`) TIDAK membuka alias), `openDocument`, notifikasi, DetailDrawer,
  PeriodUnlockBanner, aplikasi HP (`onNavigate`), `useAppNav().go`. `hubForView`/`resolveActiveNavId`/`breadcrumbFor`
  memetakan id alias (tanpa tab sendiri) ke layar utama. Palet Ctrl+K menambah "Nama lama → kini di <utama>" untuk
  alias yang punya `label` (hanya bila peran boleh membuka tujuan).
* **Layar utama membaca preset** — tanpa menyentuh AppViewRouter:
  ```js
  import useViewPreset from "../../hooks/useViewPreset";
  const preset = useViewPreset("approval-inbox");                 // null | { view, nonce, tab:"matrix", … }
  const [tab, setTab] = useState(preset?.tab || "inbox");
  // atau terapkan tiap navigasi ber-preset (juga saat layar sudah terbuka / dipasang ulang):
  useViewPreset("rnd-samples", (p) => { if (p.mode) setMode(p.mode); if (p.type) setType(p.type); });
  ```
* **Tautan di dalam layar**: `import { useAppNav } from "../../context/AppNavContext";`
  `const { go, canOpen, openDocument } = useAppNav();` →
  `go(view, { preset, tab, navId, focus: { type, id, number } })` (view boleh id lama; `focus` → jalur focusDoc),
  `canOpen(view)` (SSOT menu peran). Di luar provider (aplikasi HP) `canOpen` = false, `go` no-op.
* **App.js** (via `hooks/useAppNavigation.js`): `handleNavSelect(navId, view, tab, { preset })`,
  `navigateTo(view, { preset, tab, navId })`, `openDocument({ view, nav_id, tab, preset, focus_type, focus_id, number })`.
  AppViewRouter menerima prop baru `onNavigateTo`, `viewPreset` dan membungkus layar dengan `AppNavProvider` +
  `ViewPresetProvider`.
* **Catatan**: alamat ditulis ulang ke view utama (`?view=approval-inbox`); preset TIDAK ikut di URL — muat ulang
  halaman mendarat di tab bawaan layar utama (P8 boleh menambah bila perlu).

## 6. Risiko
1. `.tab-bar` global satu baris di HP: layar dengan banyak tab status kini bergulir ke samping (tidak membungkus);
   tab aktif digulir ke pandangan hanya untuk PageTabs (StatusTabs lama tidak).
2. Pengaturan (`settings-hub`, ±20 tab) di 1440 px membungkus 3 baris garis bawah sampai P2 memecahnya.
3. DetailModal tanpa bingkai di ≤640 px: panel anak menjadi wadah gulir (`overflow-y:auto`); panel yang kepalanya
   lebih lebar dari layar (mis. ar-aging: tombol "Tutup" di x≈403 pada 390 px — sudah begitu sebelum P1) kini bisa
   digeser ke samping; perbaikan kepala panel = paket layar (P4 untuk ar-aging).
4. Urutan efek App.js sedikit bergeser karena ekstraksi hook (sinkron sesi sebelum useAppActions) — tidak terlihat
   dampak di uji/peramban.
5. `check_nav_map` sedikit dilonggarkan khusus pola overlay (tertulis di skrip).
6. Ratchet `page_tabs` menghitung pil hitam via heuristik (ternary + `rounded-full` ±400 huruf) — bisa salah hitung
   tombol non-tab; karena ratchet, efeknya hanya baseline sedikit lebih besar.
