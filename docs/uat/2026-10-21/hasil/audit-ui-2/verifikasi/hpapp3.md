# Verifikasi audit UI tahap 2 — aplikasi HP per peran (390 px), tangkapan `hpapp3`

Disusun 26 Okt 2026 (hanya membaca; tidak ada berkas repo yang diubah). Sumber: `packets_view/hpapp3__*.md` (117 titik
awal), gambar `hpapp3/img/*.jpg`, log `hpapp3/progress.*.log` + `states.*.jsonl`, pembanding `hpapp2`. Rujukan butir:
`fixplan.md` + `fixes/G0…G5b.md`. Gambar disebut dengan nama berkas di `hpapp3/img/` (awalan path dihapus).

Cakupan: 53 butir [T]/[S] di fixplan yang menyebut HP/390 px/aplikasi HP (G0 10, G1 2, G2 10, G3 7, G4 4, G5 20).

Catatan cara baca crawl:
- Sesi crawler disuntik lewat localStorage (tanpa cookie HttpOnly). Permintaan yang ditembak komponen anak saat muat
  pertama — sebelum efek `setAuthToken` di App — mendapat **401 "Login diperlukan"**. Pola ini ada di hpapp2 (3.122× 401)
  dan hpapp3 (4.238×), jadi artefak lingkungan; dampaknya di layar dicatat terpisah (N-03).
- **states=0** untuk Ringkas/Pintasan/Tanya admin & manajer, Ringkas/Tanya finance, Ringkas desainer & admin sample:
  semuanya berurutan SESUDAH tab Notifikasi. Crawler mengetuk notifikasi → aplikasi pindah ke **mode desktop menetap**
  (`kn_force_desktop`, perilaku baru G5-09) → bilah tab HP tidak ada lagi → klik tab gagal. Lihat N-02.
- Peran `qc` & `md_quality` tidak punya titik awal sama sekali (juga di hpapp2): beranda HP mereka = halaman responsif
  `inspections` (navMeta.js:216-217 + App.js `responsiveWorkspace`), tanpa bilah tab. Lihat N-01.
- `hp-sales-aktifkan-notifikasi` states=0: butir menu berubah jadi kartu "Notifikasi HP" (G0-10) — artefak daftar titik awal.
