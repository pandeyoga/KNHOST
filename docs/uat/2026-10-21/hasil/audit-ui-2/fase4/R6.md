## 5. Journey SO — langkah dilewati ditandai server
`order_journey_service._mark_skipped`: langkah proses (selain Ditagih/Dibayar) yang belum selesai padahal langkah
SESUDAHNYA selesai → `state="skipped"` + detail "Dilewati — tidak dilakukan sebelum langkah berikutnya selesai"
(aturan sama dengan `MobileOrderJourney`); pengecualian: "Disiapkan gudang" dengan sebagian tugas siap (kirim bertahap)
→ `state="partial"` (masih berjalan, bukan dilewati). `current_step` = langkah pertama yang belum selesai & tidak
dilewati (dulu "Diverifikasi Admin Sales" walau SO sudah dikirim). `progress.skipped` baru; `progress.percent` =
(selesai + dilewati)/total (`progress.done` tetap = langkah yang benar-benar terjadi). SO batal: langkah dilewati tetap
"skipped", sisanya "cancelled" (uji lama `test_cancelled_order_journey_split` tetap cocok).

## Risiko
* `public_app_url`: instalasi yang menyetel `PUBLIC_APP_URL` tetapi sengaja ingin QR mengikuti host pemanggil (mis.
  akses LAN tanpa internet) kini selalu mendapat URL publik — itu tujuan butir 2; kosongkan env bila perlu perilaku lama.
* PATCH badan usaha yang mengirim `city` teks saja untuk badan usaha yang SUDAH berkode provinsi/kode pos kini bisa
  400 bila kota tak dikenal / tidak cocok kode pos lama (sebelumnya tersimpan apa adanya, tidak konsisten).
* `progress.percent` journey kini menghitung langkah dilewati sebagai terlewati (SO lunas tanpa verifikasi = 100 %).
* Jejak Audit & notifikasi melakukan lookup tambahan berkelompok (±0,27 s untuk 500 baris audit; ≤ 3 query per
  halaman notifikasi).
