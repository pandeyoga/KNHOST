## 2. Rincian & perubahan perilaku (untuk UAT)
**Kwitansi (HP Sales)** — form HP ringkas (jumlah, 3 metode, alokasi, catatan) diganti `ARReceiptModal`. HP kini punya:
**tanggal terima**, metode + QRIS, petunjuk kas tunai/bank, **pakai deposit pelanggan** (bila ada saldo), mode
**Otomatis (FIFO) / Manual per Pesanan**, pengingat & **keputusan selisih bayar** (`PaymentVarianceDialog`; dulu HP
diam-diam menjadikan kelebihan bayar titipan). Alur khusus HP lewat props: SO asal (`preselectOrderId`) paling atas,
mode Manual teralokasi penuh, bertanda "dibuka" (G2-21); `offline` → `offlinePost` dengan kunci idempotensi yang sama
(sinyal putus = kwitansi tersimpan di HP & dikirim sekali). `onDone(pesan, kwitansi)` (argumen ke-2 baru, desktop tidak
terpengaruh). Pesan sukses HP kini kalimat desktop ("Pembayaran AR-… (Rp …) dicatat untuk …"), juga di rincian pelanggan.
Perubahan desktop: FormModal (Esc/latar lewat tumpukan lapisan; Metode/Tanggal 1 kolom di ≤640 px); galat MUAT tetap
`ErrorNotice` (+Coba lagi) di atas, galat SIMPAN di kaki pop-up dekat tombol; tanda "dibuka" pada SO asal kini juga di
desktop; selama dialog selisih terbuka form di bawahnya tidak tertutup Esc/latar (isian tidak hilang).

**Amandemen (HP Sales)** — lembar HP (qty ± / harga / diskon per baris, chip alasan, catatan) diganti
`AmendmentProposeModal`. HP kini punya **diskon tingkat pesanan**, **tautan bukti** (nama + URL, tambah/hapus), banner
prinsip & "dokumen sudah terbit", kartu dampak yang sama dengan penyetuju, "Diusulkan oleh". Alur HP lewat prop
`autoReason`: label alasan dipilih otomatis dari jenis perubahan (harga → koreksi harga; diskon baris/pesanan → pemberian
diskon; qty → penyesuaian jumlah), hanya bila kode itu aktif di daftar alasan, berhenti begitu pengguna memilih sendiri
(desktop tanpa prop = tetap wajib pilih manual). Tombol ± qty HP hilang (tata letak; isian angka tetap). Desktop: FormModal
(hasil juga FormModal), baris dokumen di ≤640 px = nama 1 baris + 3 isian berlabel; **perbaikan**: isian harga satuan
dulu `!px-1.5` menimpa padding "Rp" (angka tertutup awalan "Rp", juga di desktop) → kini terbaca; bilah galat digulir
ke pandangan; tautan bukti 1 kolom di HP.

**PR bahan (HP MD)** — `PrCreate` dihapus, `PrCreateModal` desktop dipakai apa adanya: artikel → warna (nama KN/supplier),
pemenuhan beli/makloon, qty, roll, est. harga, subtotal/total, lokasi kirim, **supplier preferensi** (disaring
berkontrak/terdaftar + "Tampilkan semua", pagar badan usaha grup), dibutuhkan sebelum, alasan, **alasan jalur restock**,
"Langsung ajukan" (bawaan centang). Pemuatan supplier **sama dengan desktop** (`/products`, `/warehouses`, `/suppliers`,
gagal = daftar kosong) — hanya waktunya saat "Buat PR bahan" pertama diketuk (tombol "Memuat data PR…" sementara).
Pesan hasil mengikuti status server: "diajukan & langsung disetujui" / "diajukan — menunggu persetujuan" / "tersimpan
sebagai draf". Daftar PR HP: nomor dokumen realisasi dari `items[].realizations[]` (PO / Order Makloon, PO batal
diabaikan, tanpa dobel); "nomor PO/Order Makloon belum tercatat" hanya bila memang tak ada nomor.

**Ubah SKU (HP MD)** — 2 isian tanpa label → `VariantEditor` desktop (kode SKU terkunci, nama varian, nama & warna versi
supplier, harga jual dasar, status, produk unggulan, deskripsi). Induk + varian dibaca dari `/product-templates/{id}` SAMA
dengan desktop → isian harga = **harga dasar**. Ini menutup bug laten: dulu HP mengisi `price` dari daftar `/products`
yang bisa berupa harga efektif PT (`price_source=entity`) lalu menyimpannya sebagai harga dasar. Produk tanpa induk →
`global_price`. Tombol "Ubah nama / harga dasar" → **"Ubah SKU"** (label desktop untuk form yang sama; label lama salah
karena form kini mengubah lebih dari nama/harga). Sesudah simpan daftar dimuat ulang. (`CatalogDialog` kini FormModal
oleh R4 → pop-up layar penuh di HP, terlihat di peramban.)

## 5. Butuh keputusan bisnis (dipakai perilaku desktop)
1. **Catatan PR (HP)**: isian "Catatan" (`notes`) form PR HP lama tidak ada di desktop. Server menyimpannya tetapi tidak
   ada layar yang menampilkannya → kini mengikuti desktop (tanpa Catatan). Bila pemilik ingin catatan PR, tambahkan di
   `PrCreateModal` + tampilkan di rincian PR (paket purchasing).
2. **PR**: "Alasan kebutuhan" dulu wajib di HP, di desktop opsional; HP dulu selalu langsung diajukan, kini kotak
   "Langsung ajukan" (bawaan centang) — mengikuti desktop.
3. **Kwitansi lebih bayar (HP)**: dulu otomatis titipan pelanggan tanpa ditanya; kini keputusan selisih desktop
   (dialog berlabel) — sesuai FASE G-3, tetapi berarti sales HP kini diminta memutus selisih.
