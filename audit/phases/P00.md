# P00 — Rebaseline sebelum memperbaiki

Audit memakai `d1fd56e4f0fbd1af1a46bc0b9932dc8545d78467`. Paket ini dibuat di atas `3a7c40a51129aaa696e0fb5a092d9db90f1cb45f`, setelah origin/main berubah riwayat. Jangan menganggap temuan lama masih berlaku pada HEAD.

Untuk setiap ID: baca verdict/koreksi → inspeksi diff source terkait → reproduksi invariant pada current HEAD → catat commit dan hasil → open jika masih gagal, ready_for_validation jika kandidat sudah fixed, needs_policy_decision jika butuh kontrak bisnis, atau ajukan not_reproducible dengan batas fixture. Tidak mereproduksi satu fixture tidak membuktikan seluruh keluarga cacat hilang.

Simpan fixture sintetis, versi dependency, baseline test dan laporan iteration. Script reproduksi memerlukan KNHOST_REPO eksplisit dan MongoDB lokal khusus. Tidak perlu menjalankan seluruh suite historis yang mengandalkan credential/data staging tanpa menyesuaikan fixture. Jangan memindahkan baseline seluruh kartu ke HEAD hanya karena branch docs terbaru.

Fase ini dilakukan per kelompok ID; tidak harus menunda hotfix terkonfirmasi sampai 103 record direview. Output minimum: current_code_checked_commit, result evidence, classification dan daftar cabang belum diuji.
