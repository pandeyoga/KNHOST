## Prompt untuk agent develop

```text
Kerjakan fase P03: Cash, AR, bank, aset dan durable posting pada KNHOST.
1. Baca docs/audit/README.md, WORKFLOW.md, tracker.json, fase ini dan seluruh kartu finding_ids fase ini.
2. Jalankan P00: bandingkan source HEAD dengan baseline audit d1fd56e. Reproduksi pada HEAD di database sintetis; jangan menerapkan patch lama bila sudah diperbaiki. Catat current_code_checked_commit. Jika tampak sudah fixed, ajukan ready_for_validation dengan bukti; jangan tandai verified_fixed sendiri.
3. Ambil satu kelompok perubahan yang saling bergantung. Terapkan perbaikan kontrak lintas caller, bukan patch gejala satu endpoint. Pertahankan kontrol yang sudah benar. Gap kebijakan harus dibedakan dari bug yang terbukti; gunakan input pemilik proses bila keputusan bisnis memang belum ada.
4. Uji happy path, boundary, authorization, partial/reversal, failure/retry dan concurrency yang relevan. Harness arsip adalah karakterisasi bug baseline: assertion yang berhasil mereproduksi bug bukan regression pass setelah patch. Tulis regression test dengan invariant benar.
5. Perbarui hanya field implementasi/status yang diizinkan pada tracker.json. Simpan laporan dalam iterations/<tanggal>-<fase>-<slug>/ menggunakan template. Catat commit source yang diuji, test command, expected/actual, fixture, output, data migration dry-run dan batas cakupan.
6. Jangan mengubah validation_commit/validator menjadi sukses. Gunakan ready_for_validation untuk handoff; validator independen menentukan verified_fixed atau reopened. Jangan memperbaiki data produksi, menjalankan pembayaran/perangkat fisik atau deploy tanpa scope terpisah.
7. Jalankan python docs/audit/tools/validate.py. Laporkan ID selesai diimplementasikan, yang tertunda, dan urutan tindak lanjut. Jangan menyatakan seluruh fase selesai jika satu cabang/bukti masih belum ada.
```

## Exit gate

Semua ID wajib fase ini memiliki keputusan tervalidasi pada commit yang relevan, atau pengecualian/keputusan policy pemilik yang tercatat. `ready_for_validation` bukan selesai. Review harus memeriksa consumer fase berikutnya dan data historis terdampak. Tutup checklist coverage secara terpisah; memperbaiki semua temuan yang dikenal tidak berarti audit seluruh fitur selesai.
